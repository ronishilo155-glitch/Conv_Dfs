## 📌 Overview

The `sim` directory contains the cycle-accurate simulation and verification environment for the hardware accelerator. Specifically, the `t0` sub-directory serves as the primary runtime workspace where the hardware's RTL simulation outputs are rigorously evaluated against a mathematical Golden Reference model.

**Note on Software:** The initial input vectors and configurations tested in this environment are generated by the Bare-Metal host application scripts. For details on test generation, refer to the [Software README](./sw/README.md).

<a id="python-models"></a>
## 🐍 Python Verification Models

These scripts are the core of the validation methodology, responsible for generating ground-truth data and comparing results:

| File | Purpose |
| :--- | :--- |
| **`conv.new.expected.py`** | **Golden Reference Model.** A Python implementation of the targeted lightweight 2D convolution algorithm. It reads the input images and kernels, applying the exact mathematical operations to generate the ideal expected output. |
| **`check_conv_error.py`** | **Automated Error Checker.** A verification script that loads both the hardware-generated output and the Golden Reference output. It compares them element-by-element, and calculates the Mean Squared Error (MSE). |

<a id="data-logs"></a>
## 📄 Data & Log Files

During the execution of a simulation testbench, the following text and log files are utilized and generated within the `t0` directory:

### 📥 I/O Text Files
| File | Description |
| :--- | :--- |
| **`conv_config.txt`** | Contains the architectural parameters for the current run (e.g., matrix dimensions, strides). |
| **`conv_input.txt`** | The raw input image/matrix data fed into both the hardware and the Golden Model. |
| **`conv_kernels.txt`** | The 2x2 filter weights used for the convolution. |
| **`conv_expected.txt`** | The ideal output matrix generated by `conv.new.expected.py`. |
| **`conv_output.txt`** | The actual output matrix generated and written by the hardware (RTL) simulation. |

### 📊 Validation Logs
Error reports generated by `check_conv_error.py` are saved as `.log` files to track historical performance and numerical precision. The files currently in the directory serve as **examples** of the specific test cases executed during the midterm evaluation[cite: 10]:

*   **`all_errors.log`**: A general log compiling MSE results across various input sizes (from 32x32 up to 256x256) and kernel types.
*   **`all_errors32_rand.log`**: Results for a 32x32 input matrix tested with a random convolution kernel `[3, 5, 8, 2]` across eight different input value ranges (from 0-10 up to 0-256).
*   **`all_errors64_1.log`**: Results for a 64x64 input matrix tested with an all-ones baseline kernel across the eight different input value ranges.
*   **`all_errors_64_eye.log`**: Results for a 64x64 input matrix tested with an identity matrix kernel across the eight different input value ranges.

<a id="validation-flow"></a>
## 🔄 Validation Flow

The following diagram illustrates the closed-loop verification sequence, demonstrating how data flows from the initial inputs, through both the hardware and software models, down to the final error analysis:

```mermaid
flowchart TD
    subgraph Input_Data [Test Vectors]
        direction TB
        CFG(conv_config.txt)
        IN(conv_input.txt)
        KERN(conv_kernels.txt)
    end

    subgraph Execution_Engines [Processing]
        direction LR
        GOLD[conv.new.expected.py\nGolden Model]
        HW[RTL Simulation\nHardware Accelerator]
    end

    subgraph Output_Data [Generated Results]
        direction TB
        EXP[(conv_expected.txt)]
        OUT[(conv_output.txt)]
    end

    subgraph Verification [Error Analysis]
        CHK[check_conv_error.py\nMSE Calculation]
        LOG[(Validation Logs\ne.g., all_errors.log)]
    end

    %% Data Feeding
    CFG --> GOLD & HW
    IN --> GOLD & HW
    KERN --> GOLD & HW

    %% Processing to Output
    GOLD -- Generates --> EXP
    HW -- Writes --> OUT

    %% Verification
    EXP --> CHK
    OUT --> CHK
    CHK -- Appends Results --> LOG
